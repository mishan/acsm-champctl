### Follow-ups since taken

**`src/cli/args.ts` (§4.2) exists on `main`**, and all four CLIs use it. The
duplication mattered less than the identity: four `UsageError` classes with the
same name are four *different* classes, so `e instanceof UsageError` was false
for one raised by any of the others, and the first shared helper to throw one
would have lost its usage block in three of the four. Argument loops stayed put
— they have little in common and merging them would need a config object worse
than the code it replaced. Verified by building and running each CLI: all four
answer an unknown option with their own usage block and exit 3.

**The archive is SQLite** (`data/archive/archive.db`), not a directory with an
`index.json`. Every bug found in the file store was one bug in different
clothes — a body and its index entry are two writes that had to land together
and kept not doing. A row in a transaction is that guarantee, already written
and already tested. This also retired the path-safety machinery: IDs are bound
parameters now, not directory names. Node 20 is dropped, since `node:sqlite` is
unflagged only from 22.13 and absent on 20.

**Conflict surface.** The *recurring* conflicts are gone: the Status paragraph
is now one bullet per phase and the `src/` tree's `cli/` line describes the
directory rather than listing it, so each branch adds its own line instead of
rewriting a shared one.

What remains is pr5 × the stack adding a whole new README section at the same
anchor, and pr5 × pr8 adding sibling `bin`/`scripts` keys in `package.json`.
Both are **purely additive** — verified, neither side deletes or rewrites
anything the other has — so the resolution is "keep both", once, at merge.
Contorting the document order permanently to dodge a one-time keep-both
resolution would be the tail wagging the dog, so it has been left alone.

## 1. Verdict

The engineering judgement in this codebase is well above average. The reader/writer
credential split is enforced by types rather than convention, `docs/acsm-write-path.md`
records findings read off ACSM's Go source *with the author's own wrong predictions left
in and corrected*, the import guards fail closed, and at least two commits walk back an
earlier overclaim rather than leaving it standing. That habit — writing down what you
verified, what you assumed, and what being wrong would cost — is the most valuable thing
in the repo and it should not be traded away for velocity.

The defects cluster in a recognisable pattern: **the careful reasoning is applied to the
wrong value or the wrong object.** DST validation runs on the input time but the *derived*
time is what gets posted. gridmom runs against the would-be format but not the would-be
*schedule*. "No grid cap" is computed correctly and then written out as `MaxClients: 0`.
A "byte for byte" archive stores a WHATWG-decoded string. In each case the mechanism is
right and the wiring is off by one hop.

**Nothing here is ready to merge as-is.** There are 8 blockers across the four branches,
all of them small fixes. None of them require a design change.

## 4. Cross-cutting themes

### 4.1 `biome format` fails today, on every branch

`.github/workflows/ci.yml:37-38` deliberately runs lint and typecheck but not
`format:check`, and `README.md:46-50` documents the choice. The tree has since drifted:
**20 files, 35 errors** at the pr8 tip, and `main` alone already fails. Files affected
include `src/acsm/{diff,disposable,form,types,view,write}.ts`,
`src/gridmom/checks/schedule.ts`, `src/profile/load.ts`, `src/finalize/{format,plan}.ts`,
`src/emit/schedule.ts`, `src/cli/gridmom.ts`, all three `scripts/recon/*.ts`, and four
test files.

Every week this waits, the one-time diff it is being deferred to avoid gets bigger. Run
`npm run format` on `main` as its own commit, then turn on `format:check` in CI. Doing it
*before* merging four branches is much cheaper than after.

### 4.2 The CLI scaffold is now copy-pasted four times

`git grep "class UsageError"` finds four identical classes:

- `src/cli/gridmom.ts:132` (main)
- `src/cli/archive.ts:60` (pr5)
- `src/cli/finalize.ts:68` (pr8)
- `src/cli/month.ts:63` (pr8)

Plus four near-identical `for`/`switch`/`next()` loops, **three byte-identical `loadPits()`
helpers** (`gridmom.ts:162-173`, `finalize.ts:219-230`, `month.ts:159-168`), two identical
`confirm()` helpers, and four `run()`/`runCli()` boilerplate blocks. Two classes with the
same name and no shared identity will also fail each other's `instanceof`, so any shared
helper is already subtly wrong.

The `-\d` refinement at `finalize.ts:140` was applied to exactly one of the four. That is
the tell: **extract `src/cli/args.ts` before pr5 and pr8 both land**, or every future
safety fix costs four edits and someone will miss one.

### 4.3 Test fixtures are quietly dated

`test/support/build.ts:174` defines `export const NOW = new Date("2026-08-24T12:00:00-07:00")`
with the comment "Fixed clock, so schedule checks are deterministic." **`test/finalize.test.ts`
never imports it** — verified, zero occurrences of `NOW` or `now:` in the file.

`planFinalize` only forwards `now` when supplied (`plan.ts:181`), and `check()` falls back
to `new Date()` (`src/gridmom/index.ts:58`). The fixture event is scheduled
`2026-09-02T19:00:00-07:00` (`build.ts:100`). From that instant, `schedule.past`
(`src/gridmom/checks/schedule.ts:149-171`) emits a WARN on every plan, and `applyFinalize`
throws "Not saving without an acknowledgement" (`apply.ts:91-96`).

**Roughly nine tests in `finalize.test.ts` go red on 2026-09-02** — nine days from now.
One-word fix: pass `now: NOW`. Worth a repo-wide sweep for the same pattern.

### 4.4 gridmom is the safety net, and three modules disagree with it

pr7's own commit message says the goal is to stop the emitter producing months gridmom
complains about. It still does, three ways (pr7 §1.2, §1.3, §1.4), and pr6 shows gridmom
a stale schedule (pr6 §1.2). The single highest-value missing test in the whole repo:

```ts
expect(check(emitMonth(...), profile, { pits, now }).findings
  .filter(f => f.severity === "ERROR")).toEqual([])
```

That one assertion catches three of the findings below.

### 4.5 Two whole check modules are untested

No test asserts anything from `src/gridmom/checks/championship.ts` beyond `champ.no-events`
— that leaves `champ.ignore-worst`, `champ.points-places`, `champ.repeated-track`,

## 5. `main` @ `20f3cb7`

**Well done:** the reader/writer credential split as a type-level property
(`src/acsm/client.ts:16` vs `src/acsm/session.ts:193`); `docs/acsm-write-path.md`;
fail-closed import guards on an unidentifiable export (`src/acsm/write.ts:332-339`);
the 304-is-not-a-redirect reasoning (`src/acsm/session.ts:113-133`); the `ipaddr.js`
rewrite of the disposable-host check. No credential leakage and no committed secrets
found — `describeCredentialShape` (`src/acsm/session.ts:162-177`) reports shape only,
committed fixtures carry synthetic Steam GUIDs, recon artefacts are redacted.

### Major

**5.1 — The documented "omit the unpaired checkboxes" rule is implemented nowhere.**
`src/acsm/form.ts:264-270` says "champctl omits them" and `docs/acsm-write-path.md` §4
explains why: ACSM reads them positionally, a browser drops unchecked boxes, so a box
ticked on entrant 12 is applied to entrant 0. Nothing strips them.
`NON_ARRAY_ENTRY_LIST_FIELDS` only *exempts* them from `checkEntryListShape`
(`src/acsm/form.ts:302`); `postForm` passes them straight through
(`src/acsm/session.ts:402-430`); `removeAll` (`src/acsm/form.ts:238`) has no caller
outside tests. The guard should drop these keys in `postForm`.

**5.2 — An invalid `timezone` in a profile produces garbage findings instead of an error.**
`src/profile/load.ts:66-68` only checks the zone is a non-empty string. `scheduledAt`
(`src/gridmom/checks/schedule.ts:30-32`) checks `dt.isValid` *before* `setZone`, so a bad
zone yields an invalid `DateTime` returned as truthy. Downstream: `"Invalid DateTime"`
embedded in Discord messages, `scheduled.weekday` → `NaN`, and `scheduled.toISODate()!`
(`:129`) → `null` used as a Map key. One line (`IANAZone.isValidZone`) fixes it. Related:
`qualiStart` is validated as `^\d{2}:\d{2}$` (`src/profile/load.ts:63`), so `"99:99"`
passes and reaches `scheduled.set({hour: 99})` at `:58`.

**5.3 — The recon form enumerator is broken.** `scripts/recon/forms.ts:280-288` walks
forms with `form:nth-of-type(${i+1})`, but `nth-of-type` is scoped to each element's
*parent*, so it does not enumerate the document's forms. `parseForm` then takes `.first()`
of whatever matches, and the loop `break`s on the first `FormParseError`. In practice it
inspects one or two forms and reports "No schedule form found". `parseForms()` /
`findFormByAction()` already exist and do this correctly.

**5.4 — The live import-page test uses the exact anti-pattern the docs warn about.**
`test/live/acsm.live.test.ts:263-268` calls `parseForm(html)` — the first form on the page
is the navbar search form, per `docs/acsm-write-path.md` §9 and `test/form.test.ts:249` —
then asserts `enctype === "multipart/form-data"`. Should use `findFormByAction`.

**5.5 — Two whole check modules untested.** See §4.5.

### Minor

- **`checkEntryListShape` cannot see a key that is missing entirely.**
  `src/acsm/form.ts:300-322` compares counts among keys that are *present*. Per
  `docs/acsm-write-path.md` §1, a wholly absent `EntryList.Car`/`GUID` is an
  index-out-of-range panic in ACSM — the exact failure the guard exists to prevent.
  Compare against the parsed form's key set, not just the mutated payload.
- **Luxon mixes durations and wall clock.** `src/gridmom/checks/schedule.ts:56-58`:
  `derivedQuali = scheduled.plus({minutes: practice})` (exact duration) vs
  `expectedQuali = scheduled.set({hour, minute})` (wall clock). A practice spanning a DST
  transition emits a false ±60 min drift — the class of bug the module docstring
  (`:9-12`) claims to have handled. `expectedQuali` is also anchored to `scheduled`'s
  calendar day, so a practice starting before midnight reports ~1440 minutes of drift.
- **Locale-dependent prose.** No `Settings.defaultLocale` anywhere; `toFormat("cccc")`,
  `toFormat("d LLLL yyyy")` and `toRelative()` at `src/gridmom/checks/schedule.ts:88,102,141,165`
  and `checks/championship.ts:187,246` render in the host's `Intl` locale. English
  sentences come out with German weekday names under `LANG=de_DE`, and
  `test/schedule.test.ts:71-72` fails there.
- **No rate limiting on the write path.** `RateLimiter` is wired into `HttpAcsmReader`
  only (`src/acsm/client.ts:62`). `AcsmSession` — the class meant to drive a league's real
  manager — has none, despite ACSM's documented 5/20s (`src/acsm/rate-limit.ts:3-6`).
- **`RateLimiter` with `limit: 0` spins.** `src/acsm/rate-limit.ts:56`:
  `this.#timestamps[0]!` is `undefined`, giving `sleep(NaN)` in a tight loop.
- **Redirect following downgrades 307/308 to GET.** `src/acsm/session.ts:479` rewrites
  every followed hop to `method: "GET", body: null` — right for 301/302/303, wrong for
  307/308, which exist to preserve the method. It also carries the original
  `Content-Type` onto the bodyless GET.
- **Cookie jar comment overstates the code.** `src/acsm/session.ts:74-76` says "An expiry
  in the past is a delete", but only `Max-Age=0` (exactly zero, not negative) and an empty
  value are handled; `Expires` is ignored entirely.
- **Undocumented PII on disk.** `FileCache` (`src/acsm/cache.ts:28`) writes championship
  exports — driver names, Steam GUIDs, and where sign-ups are on, emails and free-text
  answers — as plaintext JSON to `.cache/acsm` under the CWD. Gitignored, but neither the
  README nor `--no-cache`'s help text mentions it. `FileCache.set` is also non-atomic
  (`cache.ts:57`), mitigated by the fail-open read at `:47`.
- **Profile fields that do nothing.** `Baseline.championship` (`src/profile/types.ts:52`)
  is never read — only `baseline.raceSetup` is (`checks/format.ts:165`) — yet
  `profiles/batl.json:24-26` sets `StartNextPracticeOnEventComplete` there and it is
  silently ignored. Same for `entryList.targetSlots` and `entryList.reservedPitBoxes`.
  A profile that advertises policy it doesn't enforce is worse than one that doesn't
  offer it. *(Note: pr7 fixes the `baseline.championship` half — `src/emit/month.ts:178`.)*
- **`ContentIndex` is an interface with no producer.** `src/content/index.ts` plus four
  checks in `src/gridmom/checks/content.ts` that can never fire — nothing constructs a
  `SnapshotContentIndex`. `README.md:195-197` admits it.
- **`validateProfile` narrows nothing.** `src/profile/load.ts:47-88`: `bad()` returns
  `never` but is called in statement position, so TS never narrows; the function ends with
  a wholesale `v as LeagueProfile` (`:84`). `:86` is a self-assignment no-op, and `:87`
  mutates the caller's object.
- **SSRF surface, small but not zero.** `HttpAcsmReader` uses `redirect: "follow"`
  (`client.ts:119`) against a user-supplied `--base-url` with no host guard — acceptable
  only because it sends no credentials; worth a comment saying so. The write path is
  correctly hardened (`session.ts:233-249`, `:472-480`) and tested.
- **The disposable guard is name-based, not resolution-based.**
  `src/acsm/disposable.ts:64-97` decides from the hostname string, so `anything.internal`,
  `foo.local`, or a bare single-label host that resolves publicly passes. The module says
  so out loud (`:9-13`) — right call for the threat model, just don't let the framing drift.
- **Untested I/O boundaries.** `FileCache`; `loadProfile` and `loadPitTable` error paths
  (`profile/load.ts:29-40`, `pits/table.ts:84-115`); `formatReport`'s dispatcher
  (`gridmom/report.ts:113`).
- **No HTML-entity round-trip test.** Everything in `test/support/acsm-html.ts` uses
  entity-free values, so nothing pins `Bob &amp; Co` or `&quot;` through
  `parseForm` → `toBody` — the highest-risk unproven property of the round-trip path.
- **Vacuous live assertions.** `test/live/acsm.live.test.ts:200`
  (`returnedCount <= sentCount`) and `:130` (`rendered === 0 || rendered === entrants`)
  pass under both outcomes. Deliberate, but they read as coverage they aren't.
- **`bin` points at unbuilt output.** `package.json:11` maps `gridmom` →
  `bin/gridmom.js`, which imports `../dist/cli/gridmom.js`, with no `prepare`/`prepack`
  hook. Low impact while `private: true`, but install-and-run is broken.

## 6. `pr5-archive-ingest` (+5, off `main`)

Nightly championship archive: fetch each export, store it if it changed, keep an index
that doubles as a change history. The design reasoning is unusually well documented. The
problems are concentrated in exactly the two places the branch stakes its reputation:
byte-fidelity, and not losing history.

**Well done:** `lastCheckedAt` advances only on a successful `put`, so a retry re-fetches
exactly the failures — correct, and pinned by `test/archive.test.ts:499-512`. The
extra-positional rejection (`cli/archive.ts:113-119`) is a good call with a good error
message. Skipping `FileCache` for archive fetches (`cli/archive.ts:194-202`) is correct
and well argued. Championship *names* never touch the filesystem — only IDs, and those go
through `assertSafeChampionshipId`. `list()` → `read()` is a genuinely closed loop.

### Blocker

**6.1 — `exportChampionshipRaw` does not return "the bytes the server sent."**
`src/acsm/client.ts:99-101` returns `(await this.#fetchJson(path)).text`, produced by
`res.text()` at `:160`. `Response.text()` performs a WHATWG UTF-8 decode: it **strips a
leading BOM** and **replaces invalid sequences with U+FFFD**. The store then re-encodes
with `writeFile(..., "utf8")` (`src/archive/store.ts:217`). Reproduced:

```
BOM body:            10 bytes in -> 7 bytes out,  byte-identical: false
Invalid UTF-8 \xff:  replaced with ef bf bd,      byte-identical: false
```

This contradicts the contract asserted in four places — `client.ts:20-28`,
`store.ts:2-11`, the new README section — and means `sha256` (`store.ts:59-61`) and
`bytes` (`store.ts:210`) describe the re-encoded string, so neither can ever be checked
against a server-side hash or `Content-Length`. Fix: `res.arrayBuffer()` → `Buffer` for
the raw path, parsing a decoded copy for validation. If that's too expensive, retract the
verbatim claim everywhere it's made — but §8.1 is the stated justification for the whole
module.

### Major

**6.2 — A torn `index.json` write silently discards the change history.**
`#writeIndex` (`store.ts:314-316`) is a plain `writeFile`: truncate, then write — verified,
no `rename` anywhere in the file. A crash or ENOSPC mid-write leaves a truncated file;
`read()` treats it as absent (`:255-259`), and `put()` writes a brand-new index (`:218-223`)
containing only the current snapshot, with `firstSeen` reset to now. Every previously
recorded snapshot vanishes from the history while the files sit orphaned on disk — exactly
what `store.ts:14-18` says the index is for. The comment at `:214-216` reasons carefully
about crash-between-the-two-writes but only in the orphaned-snapshot direction, not the
worse one. **`test/archive.test.ts:192-202` codifies the loss**: after clobbering the index
it asserts `snapshots.length === 1` with no assertion that the earlier file survives.

Fix: `index.json.tmp` + `rename()`. And either implement the rehash recovery the comment
at `:215` claims exists — it is nowhere in the branch — or stop claiming it.

**6.3 — Concurrent runs lose snapshots; no locking anywhere.** `put()` (`store.ts:196-223`)
is an unguarded read-modify-write. Two overlapping runs (a manual run during the cron
window) both `read()` the same index, both write distinct snapshot files, and the second
`#writeIndex` clobbers the first. No lockfile, no `O_EXCL`, no CAS, and nothing in the
docs acknowledges it.

**6.4 — A corrupt index makes a championship silently vanish from `status`.**
`cli/archive.ts:226`: `if (!index) continue`. `read()` returns `undefined` for both
"missing" and "wrong-shaped", so a damaged championship is dropped from the table with no
diagnostic and the count at `:252` under-reports. `status` is the command you run to find
out whether the archive is healthy — the one place that must not hide breakage.

**6.5 — The README rewrite deletes accurate documentation, and causes all three merge
conflicts.** The diff removes the Phase 2 status paragraph (session, form parser, import
safety rules, Docker harness) even though `src/acsm/{session,form,diff,write,disposable}.ts`
all exist on this branch; rewrites the `src/` tree listing to something **factually wrong
for pr5's own tree**; and deletes the paragraph "The read client and the write session are
separate types on purpose… that makes 'the bot never holds write credentials' a property
of the code" — the exact invariant pr5's own new docstrings restate three times
(`client.ts:5-8`, `ingest.ts:5-8`, `cli/archive.ts:5-7`). The roadmap line becomes
"Phases 3 onward", skipping the phase pr6/7/8 implement.

Revert the Status and tree-listing edits to `main`'s text and add the Archive section
additively. That likely reduces all three conflicts to trivial, and fixes the inaccuracy
regardless of merge order.

## 7. `pr6-finalize-engine` (+4, off `main`)

Finalize a race: read the event form, work out the diff, run gridmom against the would-be
championship, hand back something a human approves, then apply it. Writes to a live server.

**Well done:** `localTimeCandidates` (`schedule.ts:106-127`) is the right algorithm —
probing tzdata for the offsets in force ±1 day and keeping candidates that render back is
strictly better than any shift-size assumption, and it correctly subsumes both the DST gap
and the overlap into one path. Lord Howe's 30-minute shift is a well-chosen test case.
Session creation when none exists (`format.ts:163-210`) is correct and well reasoned.
Laps-win-over-minutes in `readFormat` (`format.ts:76`) matches ACSM's semantics. The
`RaceExtraLap`-is-not-a-checkbox inference (`format.ts:127-140`, docs §14) is sound and the
load-bearing step checks out — the recon capture is produced by `parseForm`, which drops

prove it. Ordering the event save before the schedule save (`apply.ts:134-142`) with an
explicit argument about which partial state is coherent is exactly right.

### Blocker

**7.1 — The validated wall clock is not the one that gets posted.**
`qualiStartFrom` (`schedule.ts:145-193`) refuses nonexistent and ambiguous *quali* times.
But the value actually transmitted is the **practice start**, derived by subtracting a
duration (`plan.ts:220`, `schedule.ts:67-69`) and re-rendered as a bare wall clock
(`schedule.ts:206-218`). That derived value is never checked. Reproduced in `node`
(America/Los_Angeles, `practiceMinutes: 60`):

```
quali  2026-11-01 02:00  -> unambiguous, passes validation, instant 10:00Z
sched  = quali - 60min                              instant 09:00Z
       renders as wall clock "01:00"
"01:00" on 2026-11-01 in LA -> TWO instants: 08:00Z (PDT) and 09:00Z (PST)
```

The POST sends `event-schedule-time=01:00` with the zone name. Go's `time.ParseInLocation`
resolves an ambiguous local time to the first match — 08:00Z — so the event is scheduled
**one hour earlier than asked for**, and `applyFinalize` reports success. This is precisely
the failure `schedule.ts:12-14` says the module exists to prevent. Nonexistent times can't
arise this way; the fall-back overlap is the live case. One night a year, silently.

Fix: run `localTimeCandidates` against `scheduleFormValues`' own output before returning,
or transmit an offset/instant rather than a bare wall clock.

**7.2 — `action=saveChampionship` is dropped, and nothing on this branch would notice.**
`acsm-champctl-plan.md:109` states the event write is
`POST /championship/{id}/event/submit` **with `Editing={eventID}` and
`action=saveChampionship`**. Both pre-existing live tests set it explicitly
(`test/live/acsm.live.test.ts:144`, `:168`). `applyFinalize` (`apply.ts:112-120`) sends
only `fresh.fields` plus the five format keys — verified, `grep` for `saveChampionship`
across `src/finalize/` and `src/acsm/write.ts` returns nothing.

On the real form `action` is not a field: the recon capture's `order` list
(`fixtures/recon/forms-v1.7.9.json`, 74 keys) contains `Editing` but **no `action`** — it
is carried by the submit button, and `parseForm` deliberately drops buttons
(`src/acsm/form.ts:142`). So `form.ts:11`'s claim to "reproduce what a browser would
submit" is false for exactly this form. Nothing in pr6 can catch it: the new harness
returns 302 for *any* POST (`test/finalize.test.ts:476-479`) and `eventFormHtml`
(`:402-438`) omits both keys. If ACSM's handler branches on `action`, the weekly write is
a no-op that redirects — and is reported as success.

Settle it before merge: send it, or record in `docs/acsm-write-path.md` that it was
empirically verified unnecessary.

**7.3 — `src/finalize/plan.ts` is a binary blob to git.** `plan.ts:124` embeds literal
`0x00` and `0x01` as hash separators. Git's binary heuristic fires, so
`git diff main...pr6` shows `src/finalize/plan.ts | Bin 0 -> 8991 bytes` — **the entire
TOCTOU guard, the fingerprint, and `planFinalize` are invisible in the PR diff.**
`git grep` reports "binary file matches" with no content; `git blame` and `git log -p` are
useless for this file permanently. `"\x00"` / `"\u0000"` escapes hash to identical bytes.
Biome's recommended preset has no rule for this and there is no `.gitattributes`, so
nothing catches it. In a PR whose thesis is "the preview cannot lie", hiding the reviewed
file from the reviewer is a bad trade for four characters.

**7.4 — gridmom is shown the would-be *format*, not the would-be *schedule*.**
`plan.ts:178-182` builds `wouldBe` from `applyFormat(ev, format)`, which touches only

### Security

### On deep-clone fidelity

There is no `structuredClone` and no JSON round-trip. The only deep copy is
`regenerateIds`' walk (`src/acsm/write.ts:132-148`), which rebuilds every object fresh.
That is what leaves the emitted championship sharing zero references with the template —
and it is **incidental**: `mergeAll` returns a shallow spread (`merge.ts:60`) whose
untouched nested values alias the template, and `buildEvent` spreads `templateEvent`
shallowly. Nothing mutates those today, so there is no corruption — but the no-aliasing
guarantee rests on a function whose stated contract is "regenerate ids", not "deep clone".
Worth a comment at minimum.

**Prototype pollution is filtered in `deepMerge` and reintroduced downstream.**
`merge.ts:49` filters `__proto__` out of the overlay and `test/emit.test.ts:99-114`
verifies it — for `deepMerge` in isolation. The template is never sanitised, and
`regenerateIds` reassigns keys with `out[k] = walk(val)` (`write.ts:145`), which triggers
the setter. Reproduced: `proto changed: true, out.polluted: true, global clean: true`.
`JSON.stringify` only serialises own properties so the import payload is unaffected; the
blast radius is in-process reads — gridmom seeing an inherited `ACSR: true` or
`SpectatorCarEnabled: true` on a championship about to be pushed.

### Minor / Nits

- **ID sweep remaps string *values*, never object *keys*.** If a future ACSM version keys a
  map by class or event UUID, values get rewritten and the key doesn't — a silently broken
  join, in exactly the unmodelled-field territory this design leans on.
- `championshipOverrides` is merged *before* the sweep (`month.ts:259-261`), so an ID a
  caller passes deliberately is silently rewritten. Untested, and absent from `derived`.
- `nextWeekday` includes today (`emit/schedule.ts:83-86`): emit at 21:00 on race night and
  round 1 lands at 19:00 the same evening, already past. `startDate` in the past isn't
  validated, and per-round `date` overrides are never checked for ordering.
- A DST-gap collision on a *generated* round throws `ScheduleError`, not `EmitError`
  (`emit/schedule.ts:69`), so callers catching `EmitError` miss it — and the message never
  names the round.
- `spec.cars` entries are neither trimmed nor validated while blank tracks are refused with
  a paragraph of justification (`month.ts:151-161`); `["", "a"]` emits `Cars: ";a"`.
- `month.ts:192` tests `SpectatorCarEnabled === true` while `view.spectatorCar`
  (`view.ts:213`) tests truthiness — on a loose export (`1`) they disagree.
- `clone.ts:58`: `cls?.Entrants ?? first?.EntryList ?? {}` — `{}` is not nullish, so a class
  with an empty entrants map never falls back to the event list.
- `RoundSpec.name` (`month.ts:71`) is declared and never read.
- `derived` is thin for the review screen it's billed as: no grid cap, no "entry lists
  rebuilt", no "results dropped", no "Scheduled regenerated", nothing for
  `championshipOverrides`.
- `key in out` (`merge.ts:64`) walks the prototype chain where `Object.hasOwn` is meant;
  `FORBIDDEN_KEYS` drops `constructor`/`prototype` at every depth, so an ACSM field so
  named would vanish.
- Dead surface: `gridCap`'s `fallback` parameter has no caller (`grid.ts:46`);
  `definedOnly` is exported and used only by its own test (`merge.ts:84`); `mergeAll` at
  `month.ts:178` is called with exactly one overlay.

### Test quality

Genuinely good: the pollution test asserts on the *result's* prototype and explains why the
global assertion would pass either way (`test/emit.test.ts:99-114`); the ID-consistency
test plants a reference in an unmodelled field (`:608-623`);
`JSON.stringify(c)).not.toContain(t.ID)` is the right shape for a sweep (`:432`); the

Weak:

  says "when an ACSM upgrade adds a field the emitter doesn't know about, that test fails
  before a Wednesday does" — a synthetic fixture never gains a field from an upgrade.
  `fixtures/synthetic/recon-seed.json` (19 top-level keys, including `SpectatorCar`,
  `OpenEntrants`, `ACSRSkillGate`) already exists and is used by the recon harness. A real

- `EXPECTED_EMIT_CHANGES` (`:40-58`) hides §8.1, and contains a dead pattern
  (`Events[n].ScheduledServerID` — spread through unchanged, so never in the diff; whether

  `exportAsReimportableCopy` clears it).
- `:466` asserts on the fixture, not the code. `:514-519` matches `derived.join(" ")`
  against three constant strings pushed unconditionally — would pass if `derived` were
  hardcoded. `:91-97` compares `JSON.stringify` before/after, blind to prototype changes

- Untested: `emitMonth` with no `pits`; `SpectatorCarEnabled: true` end to end;

## 9. `pr8-cli-and-live` (+2 on pr7)

Two CLIs (`champctl-finalize`, `champctl-month`) plus live coverage of both flows.

**Well done:** the default-inert safety ordering in both CLIs is the right design and the
reasoning is written down where it belongs. Credentials come only from
`CHAMPCTL_USERNAME`/`CHAMPCTL_PASSWORD` (`finalize.ts:359-371`, `month.ts:305-312`), never
a flag, so they stay out of argv and shell history — correct and consistently applied.
`formatFrom` starting from the current format rather than defaults (`finalize.ts:176-190`)
is the non-obvious right call and is well tested. The live gate is **fail-closed**:
`test/live/harness.ts:23-41` requires both env vars and calls `assertDisposable` at
module-eval time, so pointing it at a public host throws during *import*;
`vitest.config.ts:8` excludes `test/live/**` and `vitest.live.config.ts:11` includes only
`*.live.test.ts` with `fileParallelism: false`. `npm test` genuinely cannot touch a server,
and teardown only deletes ids the file itself created.

### Blockers

**9.1 — `--laps ""` silently means "0 laps", unguarded to the POST.**
`src/cli/finalize.ts:112-116`: `num()` is `Number(next())` with
`if (!Number.isFinite(v) || v < 0) throw`. `Number("")` is `0`. Verified:

```
["a","1","--laps",""]  => { laps: 0 }
["a","1","--laps"," "] => { laps: 0 }
```

`--laps "$LAPS"` with an unset shell variable builds `{kind:"laps", laps:0}`.
`formFieldsFor` (`src/finalize/format.ts:142-149`) then posts `Race.Laps: "0"` **and**
`Race.Time: "0"` — a race with no end condition. Nothing catches it: no range validation
in `format.ts`, and `grep -rn "Laps" src/gridmom/` returns nothing, so `plan.blocked` is
never set. `sameFormat` sees laps vs minutes as different so `plan.noop` is false, and
`--push` goes through. **This is the one path in the diff that can quietly destroy a race
night's configuration.**

**9.2 — Fractional and exotic numbers accepted for integer fields.** Same `num()`, no
`Number.isInteger` — unlike the round parser at `:161`, which has one:

```
--laps 1.5     => 1.5      (posted verbatim into a Go int field)
--reversed 1.7 => 1.7      (reaches applyFormat)
--laps 0x10    => 16
--laps 1e3     => 1000
```

**9.3 — `--push` on a non-TTY hangs, then exits 13.** `finalize.ts:232-240` and
`month.ts:184-192` build readline on `process.stdin` with no `isTTY` check. With stdin at
EOF (`< /dev/null`, a closed fd, cron), `rl.question` never settles; Node prints
`Warning: Detected unsettled top-level await` and exits **13**. `runCli` never runs, so
`process.exitCode` is never set — outside the 0/1/2/3 contract in USAGE
(`finalize.ts:61-66`) and the README. `gridmom.ts:230` already consults
`process.stdout.isTTY`, so the precedent exists. Fail fast with exit 3 and "not a terminal;
pass --yes".

**9.4 — A malformed `--spec` produces a raw `TypeError`.** `src/cli/month.ts:239` does
`readJson<MonthSpec>(...)` — a cast, not a check:

```
$ champctl-month build --spec {} --template …
champctl-month couldn't run: Cannot read properties of undefined (reading 'length')   (exit 3)
```

It dies at `src/emit/month.ts:137`. The `--template` path is handled properly
(`EmitError`), so the asymmetry is visible. Notably pr5's own commit message says "parsed
and then cast, which is not the same as checking".

### Major

- **The confirmation prompt goes to stdout, corrupting `--json`.**
  `createInterface({input: process.stdin, output: process.stdout})` (`finalize.ts:233`,
  `month.ts:185`). Under `--json --push` the plan JSON is written (`finalize.ts:311-315`)
  and then `Push this? [y/N] ` is appended to the same stream (`:328`). Prompts belong on
  stderr.
- **A partial write is reported as "champctl itself failed".** `applyFinalize` posts the
  event, then the schedule (`src/finalize/apply.ts:106-129`). If `saveSchedule` throws, the
  event **has** been saved, but `finalize.ts:336-339` never runs so "Pushed: event saved"
  never prints — and `AcsmWriteError` (`src/acsm/session.ts:34`) extends `Error`, **not**
  `AcsmError`, so `main()`'s handler at `finalize.ts:258-261` misses it and it falls
  through to exit 3, documented as "champctl itself failed". The operator is told nothing
  happened when half of it did.
- **`--quali <date>` swallows the next flag as the time.** `finalize.ts:127` calls `next()`
  twice with no lookahead:
  `["--quali","2026-09-09","--push"]` → `{quali:{date:"2026-09-09", time:"--push"}, push:false}`.
  `--push` is consumed and silently discarded. `--profile --push` behaves the same
  (`:128`). A `next()` that rejects values starting with `-` closes the whole class.
- **The arg-parsing scaffold is copy-pasted four times.** See §4.2.

### Minor / Nits

- `--flag=value` unsupported with no hint (`finalize.ts:140`, `month.ts:124`) — the single
  most common CLI muscle-memory error.
- `--` is not end-of-options in any of the three CLIs.
- Repeated flags silently last-wins, while `--laps` + `--minutes` together is a hard error
